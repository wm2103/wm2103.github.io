> 2026-10-14 进展：用户已认可 Heo / 安知鱼方向，正式 Astro 站点和八篇笔记已实现。当前方案与运行方式见根目录 README.md，以下内容作为历史参考。

> 2026-10-09 进展：已选择「布局和技术框架一起重新设计」。当前先制作三版独立 HTML 首页供比较，入口为 `previews/index.html`；选定视觉方向后再继续正式框架迁移。以下为最初方案，关于沿用 Hexo 的推荐已被上述选择取代。

目标：把旧博客整理成可以长期更新的个人网站，用于发布学习笔记、记录实践过程和展示项目。

## 当前情况

- 使用 Hexo 6.3.0 和 Butterfly 4.14.0-b2，文章以 Markdown 保存。
- 部署配置指向 `wm2103/wm2103.github.io` 的 `main` 分支；本次尚未核实线上状态。
- `source/_posts/` 有 5 篇文章，其中神经网络、Vue + Spring Boot 是内容较完整的笔记，其余是示例或空文章。
- 已有标签、分类、友链页面；导航里的关于页尚无对应源文件，也没有项目展示页。
- 站点地址仍为 `http://example.com`；主题覆盖配置混入了重复的站点配置。
- 当前目录没有源码 Git 仓库；`.deploy_git/` 留有生成页面的部署历史，不能代替源码版本管理。
- 旧笔记使用了大量外部图片；主题封面依赖随机图片接口。
- 本次已检查本地文件、配置和部署历史，尚未验证构建、外部图片或线上访问。

## 实现方式选择

### A. 沿用 Hexo，重新整理布局与内容（推荐）

保留 Markdown 写作方式和 GitHub Pages 托管，围绕现有主题增加项目展示、调整首页与阅读样式。

优点：旧内容迁移少，较快形成可用版本，后续写笔记的方式基本延续原来习惯。

取舍：大幅改变布局时需要维护少量自定义模板，日后升级主题要检查兼容性。

### B. 用 Astro 重新搭建个人网站

迁移现有文章，重新设计首页、笔记和项目模板，仍生成静态页面并部署到 GitHub Pages。

优点：首页和项目页面的设计自由度更高，适合逐步扩展为个人作品网站。

取舍：需要迁移文章元信息、核对旧链接、重建发布流程；第一版工作量更大。

当前需求主要是笔记与项目展示，优先建议 A；如果希望整体视觉和布局完全重新设计，再选择 B。

## 推荐的第一版

### 页面结构

导航：`首页 / 笔记 / 项目 / 关于`，搜索作为独立入口。

| 页面 | 主要内容 | 使用方式 |
| --- | --- | --- |
| 首页 | onlylo 的简短介绍、精选项目、最新笔记、GitHub 入口 | 让访客快速了解网站内容并进入具体文章或项目 |
| 笔记 | 文章列表、分类、标签、搜索 | 按主题查找资料，也可以按时间浏览 |
| 笔记详情 | 正文、文章目录、代码高亮与复制、上一篇与下一篇 | 优先保证长文章在电脑和手机上的阅读体验 |
| 项目 | 项目卡片、简介、技术栈、项目状态、仓库或演示入口 | 用真实项目说明做过什么，以及解决了什么问题 |
| 项目详情 | 项目背景、本人工作、主要功能、截图、相关笔记 | 在素材充分时提供完整介绍 |
| 关于 | 个人介绍、关注方向、GitHub 与公开联系方式 | 由本人提供的信息决定具体文案 |

### 视觉方向

默认采用简洁的技术博客风格：清晰的中文排版、足够留白、统一强调色，首页控制装饰图片的面积，重点呈现内容。

文章采用适合长文阅读的正文宽度；项目以卡片展示。手机上导航、目录、代码块和卡片均需可用。保留主题支持的深浅色模式，并检查自定义样式的适配。

### 内容处理

- 保留两篇完整旧笔记的正文与来源链接，整理标题、摘要、分类及标签。
- 示例与空文章移入草稿，避免在正式文章列表中占位。
- 从已有生成页面或部署记录核对旧文章地址，再处理日期与固定链接，避免因文件时间改变导致旧链接失效。
- 第一版检查旧文外部图片的可访问性；需要迁移的图片另行列出，后续新增图片优先随仓库保存。
- 项目内容使用独立数据文件维护，包括标题、摘要、技术栈、链接和精选标记。
- 项目素材未提供时显示自然的空状态，不编造项目、成果、经历或访问量。

### 写作与发布

- 继续使用 Markdown 写笔记，为新文章提供统一模板。
- 增加项目条目时主要修改数据文件，详细介绍按需补充。
- 补充 README，说明新建笔记、添加图片、维护项目、本地预览及发布的方法。
- 整理源码版本管理，忽略依赖、缓存和生成目录。
- 核实 GitHub Pages 的仓库与发布方式后，配置匹配的自动构建流程。源码分支与生成页面的用途需要明确，不能直接沿用旧部署配置来推送源码。
- 默认继续使用 GitHub Pages 地址；以后有独立域名时可绑定。

### 基础整理与验证

- 修正站点 URL，精简重复配置，补齐必要的页面与导航。
- 检查现有依赖能否在当前环境完成构建，再决定必要的版本调整。
- 验证首页、列表、文章、标签分类、项目、关于和 404 页面。
- 验证搜索、文章目录、代码复制、内部链接与静态资源路径。
- 检查桌面和手机宽度下的布局，以及旧文章链接的兼容性。

## 后续可选内容

评论、访问统计、独立域名、按系列组织的知识库，可在第一版稳定后按实际需要增加。当前内容与展示需求适合静态网站，无需先引入数据库或管理后台。
