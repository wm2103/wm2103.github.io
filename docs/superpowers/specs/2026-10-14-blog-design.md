# onlylo 博客正式改造设计
日期：2026-10-14

用户已认可 previews/04-cards.html，并授权沿此方向正式改造及整理 docs/notes。延续此前「布局和技术框架一起重新设计」的选择。

## 目标与范围
采用 Astro 静态站点；首页保留已选原型的模块化首屏、蓝紫精选、彩色分类、双列文章、作者侧栏。页面：首页、笔记列表、完整文章、苍穹外卖系列、项目、关于、404。使用真实内容，不虚构成果或日期。
导入两篇旧笔记与 docs/notes 下六篇苍穹外卖笔记，保留正文和学习批注；系列 Day 01/02/03/05/06/07 按实际顺序组织，不补造 Day 04。
长文支持层级目录、代码高亮与复制、表格横向滚动、图片加载失败提示、系列导航。全站支持搜索、主题记忆、键盘与移动端操作。

## 技术与内容边界
Astro 7.3.8（Node 24 LTS；本机使用 .tools 中的独立 Node，不修改全局 Node 20），TypeScript，Astro Content Collections，Markdown，原生少量客户端脚本。构建产物 dist，静态资产 static，不混用旧 public 目录。
原始 source/_posts 和 docs/notes 保留；脚本将整理后的正文与元数据导入 src/content/notes，可重复执行。元数据保留在 scripts/note-catalog.mjs，新增文章直接写 src/content/notes。原始日期无法确认的新笔记不填虚构发布日期，可记录 importedAt 并明确表示整理日期。
公开内容中若发现实际明文凭据，仅在导入副本中替换为占位符，原文不动；报告只记录位置和类型。缺失本地图片显示明确占位说明，保留文件名于迁移报告。外链图片保留原 URL，不把它们当作已离线保存。
支持 /notes/<slug>/ 稳定路径，以及两篇旧日期路径的静态跳转页。site 使用已有 wm2103.github.io 地址；配置可用环境变量覆盖。
不执行远程推送或上线。配置 GitHub Pages Actions，并说明当前目录没有源码 Git 仓库，.deploy_git 是旧发布历史。

重复导入仅更新清单管理的八篇文章，其他新写文章不改动；importedAt 为固定首次整理日期。部署目标为已知的根域用户站 wm2103.github.io（base 为 /），README 明确不直接支持项目仓库子路径。

## 验收
内容迁移与路径处理用 Node 测试；Astro check、生产 build、生成页面链接检查；浏览器检查首页/列表/完整长文/系列/项目/关于/404、搜索、筛选、主题、目录、代码复制、移动导航；360–1920 像素无页面横向溢出。README 写清安装、预览、写作、导入、部署。


## 实现调整
依赖核对显示 Astro 5 已落后于当前维护版本，正式实现改为 Astro 7.3.8。升级后使用 astro/zod 的当前 schema 接口。依赖补丁核对后 npm audit 报告为 0。
使用 Astro 7 的原生 Sätteri Markdown 处理器，在构建时为正文图片加入懒加载、异步解码与 referrer policy；同时覆盖 Markdown 与内嵌 HTML 图片。当前依赖最低 Node 版本为 22.19，推荐 Node 24 LTS。
构建验证按实际发布集合检查文章数量、RSS 与搜索索引，长文完整性检查仅针对迁移清单。新增短文与草稿通过独立写作流程验证脚本检查。
